## AC-02 정원 마감 시 신청 거절과 다른 챌린지 안내

| 항목 | 내용 |
|---|---|
| 기준 | 정원이 찬 챌린지 신청은 거절되고 신청이 생기지 않는다. 사용자에게 다른 챌린지를 둘러보도록 안내한다 |
| 입력 1 | 정원 60, 참여 59인 챌린지에 학생 A·B가 동시에 신청 |
| 입력 2 | 정원 100/100 챌린지의 탐색 카드·소개 페이지 열기 |
| 기대 | 1건만 성공, 다른 1건은 "정원이 다 찼어요. 비슷한 챌린지를 둘러볼까요?", 정원 초과 없음 / 카드·소개에 "정원 마감", 신청하기 버튼 없음 |
| 구현 위치 | `server/store.ts:284` 정원 확인, `supabase/migrations/0004_enroll_capacity.sql`(신청 직전 챌린지 행 잠금·재확인), `app/c/[id]/page.tsx` Cta(정원 마감 시 비활성 버튼) |
| 관련 TC | TC-FN-ENR-001(통과, 결함 수정 `c46a189`·`18acf30` 후 운영 재실행), TC-FN-DISC-004(통과) |
| 현재 판정 | **부분 통과** — 거절과 정원 유지는 운영에서 확인. "다른 챌린지 안내"는 거절 문구 한 줄뿐이고, 탐색으로 가는 링크나 다른 챌린지 목록은 화면에 없음(코드 확인). 정원 마감 소개 페이지에는 비활성 "정원 마감" 버튼만 있고 안내 문구가 없음 |
| 남은 범위 | 안내를 문구로 충분하다고 볼지, 이동 링크까지 요구할지 기준 결정 필요(담당 미정) |

## AC-03 인증 마감 23:59 경계

| 항목 | 내용 |
|---|---|
| 기준 | Day N 인증은 그 날 23:59:59.999(KST)까지 받고, 다음 날 00:00:00.000부터 거절한다 |
| 입력 | 서버 수신 시각 12-03 23:59:59.999 / 12-04 00:00:00.000 (Day 3 = 12-03) |
| 기대 | 앞은 성공 / 뒤는 "아쉽지만 인증 마감(23:59)이 지났어요", 인증 미생성, 입력은 기기에 유지 |
| 구현 위치 | `domain/day-calendar.ts` `deadline()`(배타적 마감 = 다음 날 00:00 KST), `server/store.ts:369` 거절 문구 |
| 관련 TC | TC-FN-SUB-002(통과, V), TC-FN-SUB-003(통과, E·V), TC-FN-TIME-001(통과, V), TC-FN-TIME-002(통과, E), TC-FN-CUR-004(부분 통과) |
| 현재 판정 | **부분 통과** — 경계값은 단위 테스트(V)로만 통과. 운영 서버 시각을 고정할 수 없어 경계 시각 E2E는 **미실행**. 화면에서는 마감 지난 Day에 인증 폼이 없음을 확인(E). SQL `day_is_open` 함수는 없음 |
| 남은 범위 | 서버 시각 주입(테스트 전용) 방식 결정 후 E2E 재실행 |
