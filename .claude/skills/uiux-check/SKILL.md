검토할 시안 설명 경로는 $ARGUMENTS 로 받습니다. 파일은 읽기만 하고 수정하지 않습니다.

## 근거 문서 (챌린지업)

- 요구사항: `waterfall/01-요구사항분석/요구사항명세서-SRS.md` (FR-013 Day 열람, FR-014 오늘의 미션, FR-015 미션 인증)
- 화면 명세: `waterfall/02-시스템설계/화면설계서.md` (SCR-EXP-01 오늘의 미션, SCR-DAY-01 Day 상세 + 인증, 2.3 360px·키보드·대비 공통 기준)
- 단계 계획: `PLAN.md` (지금 단계에 들어가는 범위와 후속 작업)

## 절차

1. $ARGUMENTS 가 `.md` 파일 한 개인지 확인하고 연다. 없거나 여러 개면 `INPUT ERROR: [이유]` 한 줄만 쓰고 멈춘다.
2. 위 근거 문서 세 개를 연다. 하나라도 읽지 못하면 `INPUT ERROR: [경로]` 로 멈춘다.
3. 아래 R1~R4를 각각 PASS · REVIEW · UNVERIFIED 중 하나로 판정한다.
   - **PASS**: 시안에 기준을 만족하는 근거 문장이 있다.
   - **REVIEW**: 시안이 기준을 명시적으로 어기거나, 기준이 요구하는 것을 빠뜨렸다.
   - **UNVERIFIED**: 판단할 근거가 시안에 없다. 브라우저·키보드로 실제 실행한 기록이 없으면, 실제 동작은 항상 UNVERIFIED다.
4. R3은 **설계 판정**(시안이 무엇을 의도하는지)과 **실행 판정**(실제로 관찰한 기록이 있는지)을 따로 적는다.
5. REVIEW·UNVERIFIED마다 다음 조치를 하나씩 제안한다. 파일은 고치지 않는다.

## 규칙

| 규칙 | PASS 조건 | REVIEW 예 |
|---|---|---|
| R1 시각 위계 | 오늘 미션 제목 · 마감(오늘 23:59) · 주요 버튼 '인증하기'가 **스크롤·펼치기 없이 첫 화면에** 보인다. 파란 주요 버튼은 화면에 하나뿐이다 | 인증하기가 '더 보기'·접힘·탭 안에 있음. 주요 버튼이 둘 이상 |
| R2 상태 피드백 | 인증 완료 · 오늘 미션 없음 · 오류 · 마감 지남을 **각각 다른 문구**로 구분하고, 오류에는 '다시 시도' 같은 다음 행동이 있다. 저장 실패에도 입력이 남는다 | 미션 없음과 오류를 한 문구로 합침. 오류 뒤 할 일이 없음. 실패하면 입력이 지워짐 |
| R3 반응형·접근성 | 설계: 360px에서 1열이고 가로 넘침이 없으며, 포커스 표시와 Tab 순서, 터치 영역 44px가 적혀 있다. 실행: 브라우저·키보드로 확인한 기록이 있다 | 고정 폭(예: 1200px), 포커스 숨김, 터치 영역 44px 미만 |
| R4 지금 단계 범위 | 미션 · 마감 · 인증하기 표시와 텍스트·링크·체크 인증까지. 범위 밖 기능(사진 업로드·강사 확인은 `PLAN.md` 5단계 미구현, 결제는 SRS FR-024 P4 제외)은 **화면에 없거나 '후속 단계'로만 표시**되면 PASS. 근거로 해당 문서 위치를 인용한다 | 사진 업로드나 결제를 이번 단계 화면에 넣음 (PLAN.md 범위 밖) |

## 출력 형식

| 기준 | 판정 | 파일 · 관찰 근거 | 다음 조치 |
|---|---|---|---|
| R1 | … | `경로` "인용" | … |
| R2 | … | … | … |
| R3 설계 | … | … | … |
| R3 실행 | … | … | … |
| R4 | … | … | … |

마지막 줄에 `전체: PASS | REVIEW` 를 쓴다. REVIEW가 하나라도 있으면 REVIEW다. UNVERIFIED는 전체 판정을 바꾸지 않지만, 개수는 따로 적는다.
